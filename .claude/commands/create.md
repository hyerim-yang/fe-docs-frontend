## 입력

사용자가 제공한 인자: $ARGUMENTS

인자는 **없어도 됩니다**. 없으면 1단계부터 하나씩 물어봅니다.
인자가 있으면 가능한 부분을 자동 파싱하고, 부족한 정보만 물어봅니다.

인자 형식 (선택): `<폴더명> <문서제목> <작성자>`
예시: `/create git-guide Git 브랜치 전략 가이드 홍길동`

## 규칙

1. **반드시** `src/app/docs/_template/page.tsx` 템플릿을 기반으로 생성할 것
2. 템플릿의 레이아웃, 스타일, 구조를 절대 변경하지 말 것
3. 아래 절차를 **순서대로** 수행하고, **각 단계마다 사용자 확인**을 받을 것
4. 사용자가 선택할 수 있도록 번호 옵션을 제시할 것

## 절차

### 1단계: 기본 정보 수집

인자가 제공되었으면 파싱한다:

- 첫 번째 단어 → 폴더명 (kebab-case, 영문)
- 마지막 단어 → 작성자
- 중간 단어들 → 문서 제목

**부족한 정보는 하나씩 물어본다:**

1. **문서 제목**: "문서 제목을 입력해주세요 (예: Git 브랜치 전략 가이드)"
2. **폴더명**: "폴더명을 입력해주세요 (영문 kebab-case, 예: git-guide)" — 제목 기반으로 추천도 함께 제시
3. **작성자**: "작성자 이름을 입력해주세요"

### 2단계: 카테고리 선택

`src/lib/docs.ts`의 기존 카테고리 목록을 읽어서 번호 옵션으로 제시한다:

> **카테고리를 선택해주세요:**
>
> 1. 온보딩
> 2. FrontEnd
> 3. 팝테일
> 4. 팝테일 에디터
> 5. 팝테일 파트너 사이트
> 6. 팝키즈
> 7. Study
> 8. ✨ 새 카테고리 직접 입력
>
> (번호를 입력해주세요)

- 8번 선택 시 카테고리명을 직접 입력받는다
- **중요**: 목록은 하드코딩하지 말고, `docs.ts`에서 고유한 `category` 값을 추출하여 동적으로 생성할 것

### 3단계: 태그 선택

`src/lib/docs.ts`의 `tagVariant` 객체에서 기존 태그 목록을 읽어서 번호 옵션으로 제시한다:

> **태그를 선택해주세요 (복수 선택 가능, 쉼표로 구분):**
>
> 1. 온보딩
> 2. 기술
> 3. 서비스
> 4. 트러블슈팅
> 5. 스터디
> 6. 정책
> 7. ✨ 새 태그 직접 입력
>
> (번호를 입력해주세요, 예: 2 또는 2,4)

- 복수 선택 가능 (쉼표 구분)
- 7번 선택 시 태그명을 직접 입력받는다
- 새 태그 입력 시 `tagVariant`에 적절한 색상 스타일도 추가할 것

### 4단계: 문서 설명 입력

> **문서 설명을 입력해주세요** (목록에 표시될 한 줄 설명):
>
> 예: "Git 저장소 세팅, 토큰 발급, Clone 방법 및 브랜치 전략 안내입니다."

### 5단계: 본문 내용 생성

사용자에게 선택지를 제시한다:

> **본문 내용을 어떻게 작성할까요?**
>
> 1. 🤖 AI가 주제에 맞게 자동 생성 — 주제/키워드만 알려주세요
> 2. 📋 내용 붙여넣기 — 텍스트, 메모, md 등을 붙여넣으면 템플릿에 맞게 변환
> 3. 📝 빈 템플릿으로 생성 — 나중에 직접 작성
>
> (번호를 입력해주세요)

**1번 선택 시:**

- "어떤 내용을 다루면 좋을까요? 주제, 키워드, 또는 간단한 설명을 입력해주세요" 라고 물어본다
- 사용자 입력을 바탕으로 문서 내용을 생성한다
- 생성 시 템플릿의 스타일 클래스를 그대로 사용한다 (아래 "본문 작성 규칙" 참조)

**2번 선택 시:**

- "변환할 내용을 붙여넣어 주세요 (텍스트, 메모, md, 파일 경로 등 아무 형식이나 OK)" 라고 물어본다
- 사용자가 붙여넣은 원본 내용(텍스트, 메모, md, 노션 복사 등 어떤 형식이든)을 분석한다
- 파일 경로가 제공된 경우 해당 파일을 읽어서 내용을 가져온다
- 원본의 구조와 정보를 최대한 유지하면서, 템플릿의 스타일 클래스에 맞게 JSX로 변환한다
- 마크다운 문법(`#`, `-`, `**`, `` ` `` 등)은 대응하는 JSX 요소로 변환한다
- 생성 시 템플릿의 스타일 클래스를 그대로 사용한다 (아래 "본문 작성 규칙" 참조)

**3번 선택 시:**

- 섹션 예시 하나만 남긴 빈 템플릿으로 생성한다

**선택지를 건너뛰는 경우:**

- 사용자가 4단계 이전이라도 본문 내용을 직접 붙여넣거나 "이 내용으로 문서 작성해줘" 같이 명령하면, 5단계 선택지를 건너뛰고 바로 2번(내용 붙여넣기) 방식으로 처리한다

### 6단계: 최종 확인

지금까지 수집한 정보를 요약하여 보여준다:

> **📋 생성할 문서 정보:**
>
> | 항목     | 값                                     |
> | -------- | -------------------------------------- |
> | 제목     | Git 브랜치 전략 가이드                 |
> | 폴더명   | git-guide                              |
> | 작성자   | 홍길동                                 |
> | 카테고리 | FrontEnd                               |
> | 태그     | 기술                                   |
> | 설명     | Git 브랜치 전략과 컨벤션을 안내합니다. |
> | 본문     | AI 자동 생성                           |
>
> **진행할까요? (Y/n)**

### 7단계: 파일 생성

1. `src/app/docs/_template/page.tsx` 파일을 읽는다
2. `src/app/docs/<폴더명>/page.tsx` 경로에 새 파일을 생성한다
3. `meta` 객체를 수정한다:
   - `title` → 문서 제목
   - `author` → 작성자
   - `createdAt` → 오늘 날짜 (YYYY-MM-DD)
   - `updatedAt` → 오늘 날짜 (YYYY-MM-DD)
4. 함수명을 `TemplatePage`에서 폴더명 기반 PascalCase로 변경한다 (예: `git-guide` → `GitGuidePage`)
5. 상단 주석 블록(사용법 안내)은 제거한다
6. 5단계에서 AI 생성을 선택한 경우, 본문 영역에 내용을 채운다

### 8단계: docs.ts에 등록

`src/lib/docs.ts`의 `docs` 배열 맨 끝에 새 항목을 추가한다:

```ts
{
  title: "<문서 제목>",
  description: "<문서 설명>",
  author: "<작성자>",
  date: "<오늘 날짜 YYYY-MM-DD>",
  category: "<선택한 카테고리>",
  tag: "<선택한 태그>",        // 태그가 1개면 string, 2개 이상이면 string[]
  href: "/docs/<폴더명>",
}
```

### 9단계: 검증 및 완료

1. `npm run lint`로 린트 검사를 실행한다
2. 에러가 있으면 자동 수정한다
3. 최종 결과를 보여준다:

> **✅ 문서가 생성되었습니다!**
>
> - 파일: `src/app/docs/<폴더명>/page.tsx`
> - 등록: `src/lib/docs.ts`
> - URL: `/docs/<폴더명>`

## 본문 작성 규칙

AI가 본문을 생성할 때 반드시 지켜야 할 규칙:

- 최상위 `<div className="space-y-14 ...">` 안에 `<section>` 단위로 작성
- 섹션 제목: `<h2 className="text-xl font-semibold text-foreground mb-4">`
- 본문 텍스트: `<p>` 태그 사용
- 리스트: `<ul className="list-disc pl-5 space-y-1">` 또는 `<ol className="list-decimal pl-5 space-y-1">`
- 코드 블록: `<pre className="bg-muted rounded-lg p-4 overflow-x-auto"><code>...</code></pre>`
- 인라인 코드: `<code className="bg-muted px-1.5 py-0.5 rounded text-sm">...</code>`
- 강조 박스: `<div className="bg-muted rounded-lg p-4 border">`
- 테이블: `<table className="w-full border-collapse">` + `<th className="border px-3 py-2 bg-muted">` + `<td className="border px-3 py-2">`
- 템플릿에 없는 외부 클래스나 구조를 임의로 추가하지 말 것
- 뒤로가기 링크, 제목/메타 헤더 영역의 마크업은 그대로 유지할 것

### 섹션 제목 이모지 규칙

각 `<h2>` 섹션 제목 앞에 내용에 어울리는 이모지를 추가하여 시각적으로 구분한다.

- 이모지는 제목 텍스트 앞에 한 칸 띄워서 배치한다
- 예: `<h2 ...>🔗 Aipia Vercel URL</h2>`, `<h2 ...>🌐 Domains | 도메인 등록하기</h2>`
- 자주 사용하는 이모지 참고:
  - 🔗 링크/URL 관련
  - 🌐 도메인/네트워크 관련
  - ⚙️ 설정/환경 관련
  - 🔧 도구/설치 관련
  - 📦 패키지/배포 관련
  - 🚀 시작/실행 관련
  - 📝 작성/문서 관련
  - 🔑 인증/보안 관련
  - 🗂️ 구조/아키텍처 관련
  - ✅ 체크리스트/완료 관련
  - ⚠️ 주의/경고 관련
  - 💡 팁/참고 관련
- 문맥에 맞는 이모지를 자연스럽게 선택하되, 같은 문서 내에서 중복 사용을 피한다

## 중요

- 각 단계에서 사용자 응답을 기다린 후 다음 단계로 넘어갈 것
- 카테고리/태그 목록은 `docs.ts`에서 **동적으로** 읽어올 것
- 이미 존재하는 폴더명이면 경고하고 다른 이름을 제안할 것
